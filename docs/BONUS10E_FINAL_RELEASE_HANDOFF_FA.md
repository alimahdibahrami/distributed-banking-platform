## محدودیت‌ها — ادعای امتیاز کامل نکنید

1. این تست یک **Controlled Cutover با وقفه** بوده و شرط «بدون توقف سامانه» بونوس ۱۲٪ را اثبات نکرده است؛ Gateway و چند سرویس در انتشار Epoch جدید Recreate شده‌اند.
2. سناریوی Crash پنجم بعد از *انتشار فایل Map* و پیش از Restart بوده، درحالی‌که صورت تکلیف خرابی **بعد از فعال‌سازی Map و قبل از پاک‌سازی داده قدیمی** را می‌خواهد. در این پیاده‌سازی Cleanup زودتر از انتشار Map انجام می‌شود؛ پس تطابق کامل با آن الزام اثبات نشده است.
3. شواهد 2PC بعد از Cutover قوی‌اند، اما Exactly-Once و Client Request ID و انتقال بین‌شاردی حین مهاجرت در همه نقاط بحرانی هنوز با آزمون نهایی استاد پوشش داده نشده‌اند.
4. Crash در این آزمایش عمدتاً با توقف عمدی *فرایند Operator* (`os._exit(86)`) شبیه‌سازی شده، نه الزاماً `docker kill` کانتینر برنامه بانکی. این تمایز را در گزارش ذکر کنید.
5. کد آزمایشگاه جدا از استقرار اصلی است؛ این Patch به‌تنهایی جایگزین Compose اصلی یا یک Release سه‌شاردی Production نمی‌شود.

## بازتولید آزمایش در محیط **کاملاً تازه**

1. پوشه `labs/distributed-banking-b10e5-crash-lab` را بدون `.env` و بدون Volumeهای قبلی به مسیری با نام `distributed-banking-b10e5-crash-lab` در VPS منتقل کنید.
2. فقط در محیط ایزوله و دارای ظرفیت کافی: `bash scripts/preflight_lab.sh` و سپس `bash scripts/start_lab.sh`.
3. فقط یک‌بار: `bash scripts/crash_matrix.sh`. اگر مرحله‌ای قطع شد، از ابتدا تکرار نکنید؛ وضعیت را با `bash scripts/operator.sh status` بخوانید.
4. بعد از پایان موفق: `python3 scripts/verify_final.py`.
5. هرگز `.env` یا Volumeهای PostgreSQL را به Git منتقل نکنید؛ هرگز روی سرور فعال `docker compose down -v` یا `docker system prune` اجرا نکنید.
