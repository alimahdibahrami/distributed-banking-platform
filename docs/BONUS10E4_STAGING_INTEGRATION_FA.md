# فاز ۱۰E-4A: اتصال Snapshot و Replay به PostgreSQL با Staging مستقل

این بسته با هدف نزدیک شدن به اجرای واقعی مهاجرت آنلاین، ماژول PostgreSQL به مسیر سورس اصلی می‌افزاید، ولی **هرگز Cutover را انجام نمی‌دهد**. مرجع آن Commit `a806072` روی Branch توسعه است.

## تغییرها

- گرفتن Snapshot سازگار از حساب‌های A1501..A2000 در B، پس از فعال شدن CDC. تراکنش خواندن، Repeatable Read و Read Only است.
- انتقال داده فقط به `bank_migration_stage_accounts` در دیتابیس آزمایشی C؛ جدول `accounts` موجود، موجودی‌های واقعی، شارد مپ و Coordinator تغییر نمی‌کنند.
- Replay تغییرات بر اساس `(account_id, account_revision)` با کنترل دریافت تکراری، رسید پایدار، رد پرش نسخه و جلوگیری از عقب رفتن موجودی.
- خواندن کل رویدادهای CDC در هر دور به‌جای اتکا به `MAX(event_id)`، چون PostgreSQL sequence معادل ترتیب COMMIT نیست.
- ممیزی تطابق ۵۰۰ حساب پس از اینکه B واقعاً Fenced شود؛ نتیجه فقط وضعیت Data Convergence را نشان می‌دهد، نه مجوز Cutover.

## موارد مهمی که هنوز باید انجام شوند

۱. ساخت اپراتور و مجوز DB مختص مهاجرت، جدا از کاربر بانک.
۲. نصب DDL روی **دیتابیس آزمایشی ایزوله** و تست PostgreSQL واقعی (Snapshot/Replay/Restart/2PC).
۳. اتصال کنترل‌پلین SQLite به خروجی معتبر DB، پیاده‌سازی Barrier و در نهایت Activation و Cleanup با 2PC تاریخی.
۴. گردش Cutover بدون توقف عملیات برای کل سامانه: هماهنگ‌سازی Gateway/Coordinator/Replica و جلوگیری از Split-Brain.

## سیاست ایمنی

- این بسته فقط فایل جدید به Branch توسعه اضافه می‌کند، `main` و VPS فعلی نباید تغییر کنند.
- کد جدید هیچ API اجرایی عمومی و هیچ CLI برای تغییر مالکیت ندارد.
- SQL فقط Staging Table را اضافه می‌کند؛ روی سرور اصلی اجرا نشود.
- تست‌های Unit و Contract جای تست واقعی PostgreSQL نیستند؛ تا PASS شدن آزمایش عملی، امتیاز بونوس نهایی تأیید نمی‌شود.
